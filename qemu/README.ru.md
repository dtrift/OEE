# oee-qemu — узел A на LM3S6965 (QEMU)

Портабельность недели 6: та же int8-модель A, что работает в хостовых узлах
(`ml/models/model_a.tflite`), скомпилирована в `no_std`-прошивку под
Cortex-M3 отладочной платы LM3S6965 — машину, на которой тестирует сам автор
MicroFlow (план, раздел 7). Фиксированные окна на вход, вероятности классов
и argmax на выход через UART0; выход из QEMU — semihosting, поэтому запуск
скриптуемый.

Пакет не входит в воркспейс OEE: он исключён в корневом `Cargo.toml`
(крейт под `thumbv7m` не должен попадать в хостовые сборки) и несёт свой
`[patch.crates-io]` для nalgebra форка.

## Первичная настройка

```bash
rustup target add thumbv7m-none-eabi
cargo install flip-link                  # линкер из .cargo/config.toml
# QEMU: либо нативный бинарник (apt install qemu-system-arm), либо docker —
# scripts/qemu.sh сам выбирает нативный, если он есть:
docker build -t oee-qemu qemu/
```

## Команды

```bash
# демо-прошивка: 4 фиксированных окна -> вероятности в UART
cd qemu && cargo run --release --bin oee-qemu

# паритет хост/QEMU (гейт D2): собирает обе стороны, сверяет бит-в-бит
scripts/qemu-parity.sh

# flash/RAM трёх вариантов (conv1d / трюк conv2d / dense-пол)
scripts/footprint.sh
```

Фиксированные окна берутся из `ml/models/model_a.val.csv` (первая строка
каждого класса) скриптом `scripts/gen-qemu-windows.py`; прошивка
(`src/windows.rs`) и хост-эталон (`nodes/examples/qemu_host_ref.rs`)
включают один и тот же сгенерированный файл — паритет сравнивает
идентичные биты.

## Три бинарника

| Бинарник   | Что это                                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `oee-qemu` | демо: модель A через выделенное ядро `conv_1d` (путь `#[model]` по умолчанию)                                                                          |
| `conv2d`   | ТА ЖЕ модель, принудительно через общее ядро `conv_2d` (трюк reshape) — только для замеров (`--features footprint-conv2d` + `MICROFLOW_CONV2D_ONLY=1`) |
| `dense`    | сериализационная игрушка недели 1 (только полносвязные слои, случайные веса) — «пол» движка без conv-ядра                                              |

## Честные ограничения

- Драйвер UART — только TX, без прерываний; он рассчитывает на то, что QEMU
  стартует плату с уже тактированным UART0, подключённым к serial-бэкенду —
  на реальном кремнии сперва нужны мультиплексирование GPIOA и включение
  UART.
- QEMU не циклоточен: скоростные числа берутся из хостовых criterion-бенчей
  (`fork/microflow/benches/conv1d.rs`); QEMU доказывает портабельность и
  footprint.
- Вариант `conv2d` обязан собираться в своём `CARGO_TARGET_DIR` (cargo не
  фингерпринтит env-чтения proc-макросов — см. `src/bin/conv2d.rs` и
  `scripts/footprint.sh`).
