## Д1 (пн, ~2–3 ч) — узел P: счёт

1. События IR-барьера из симулятора (разд. 4): джиттер интервалов, иногда две
   детали подряд, иногда пропуск.
2. Детектор фронта + окно анти-двойного-счёта (два события внутри окна = одна).
3. Ground truth: счёт сценария vs счёт узла — совпадение на базовом прогоне.

Проверка: на сценарии с двойными и пропусками счёт P корректен.

## Д2 (вт, ~2–3 ч) — агрегатор: формула OEE

1. Подписка на `oee/line1/*`; окна агрегации: минута и смена (разд. 1).
2. Формулы: A = Run/Planned, P = IdealCycle×Count/RT, Q = Good/Total (или 1.0).
3. Публикация `oee/line1/oee` + компоненты; CSV-лог для отчёта.

Проверка: на ручном сценарии компоненты сходятся с truth по построению.

## Д3 (ср, ~3 ч) — TUI-дашборд на ratatui

Новый крейт `oee-dashboard` (6-й в workspace), весь стек остаётся на Rust. Слои:

| Слой                   | Что делает                                       | Тесты      |
| ---------------------- | ------------------------------------------------ | ---------- |
| MQTT-поток (rumqttc)   | подписка `oee/line1/#` → mpsc-канал              | реюз узлов |
| `DashboardState`       | чистая `on_message(topic, payload)` — вся логика | юнит-тесты |
| рендер `ui(f, &state)` | Gauge OEE/A/P/Q, счётчик, вердикты, Sparkline    | глазами    |

1. (0:00–0:20) каркас крейта, `ratatui::init()`, hello-world на экране.
2. (0:20–0:50) MQTT-поток (копипаста подписки из узла недели 4) + канал + статус-бар
   «обновлено N с назад» (замечает обрыв брокера).
3. (0:50–1:40) `on_message`: JSON `oee/line1/oee` (схема из Д2), цвета зон (зелёный
   ≥85%, жёлтый ≥60%), счётчик P, лента вердиктов Q; юнит-тест на битый payload —
   мусор не роняет витрину (error isolation).
4. (1:40–2:10) Sparkline истории OEE; перерисовка по тику ~5 fps, `q` — выход;
   `ratatui::restore()` по panic hook.
5. (2:10–3:00) полный прогон со стендом, узкий терминал, буфер.

Таблица «measured vs truth» — из CSV агрегатора, в TUI не тащим.

Проверка: при прогоне симулятора цифры живут и меняются; `cargo test` крейта зелёный.

Запасной план: ratatui буксует дольше ~1,5 ч → Node-RED в контейнере (старый вариант
Д3, виджеты без кода); минимальный fallback — MQTTX (~15 мин, живой просмотр топиков).

## Точки эскалации

- Измеренный OEE сильно ≠ истинный → сверять по компонентам (A, P, Q отдельно),
  не по итоговой цифре; чаще всего виновато окно анти-счёта P или окна A.
- ratatui буксует → запасной план: Node-RED в контейнере (~1 ч, виджеты без кода);
  минимальный fallback — MQTTX (живой просмотр `oee/line1/#`, ~15 мин). На гейт не
  влияет: главный артефакт недели — таблица measured vs truth, а не витрина.
- Сценарии дают «идеальные» 0% ошибки → ужесточить шум/джиттер, иначе таблица
  неубедительна (риск «слишком хорошо», разд. 11).
