# Recommendations: qemu + firmware

- **Severity**: recommendation
- **Component**: firmware
- **Source**: code review `backlog/20260909120000-review.md` (Russian original), appendix A6, "Recommendations"

1. **Pin the contract constants with tests**: `firmware-a`/`firmware-q` already depend on `features-cli` — a host test `assert_eq!(WINDOW, features_cli::window_spec(NodeKind::A).unwrap().samples)` (and for Q); `qemu` can take the dependency (features-cli is `#![no_std]`). Details: `20260909120007-important-features-cli-contract-drift-workspace-bl.md`.
2. **A property-style trace after the P fix** (`resolved/20260909120005-critical-counts-levels-not-edges-firmware-p-bl.md`): run `bounce/held-high/wrap` from the firmware against the host `nodes::p::EdgeCounter` on identical inputs — that is the declared "mirroring".
3. **CI**: add a `qemu` job and `--release` to the `firmware` job — see `20260909120031-important-qemu-not-in-ci-ci-bl.md`.
4. **Q bring-up**: check the stack high-water mark before moving to real I2S (DMA buffers add on top) — the measured ~294 KiB headroom is documented in the README (see `resolved/20260909120032-important-q-stack-overflow-firmware-q-bl.md`).
