# Minor: qemu

- **Severity**: minor
- **Component**: qemu
- **Source**: code review `backlog/20260909120000-review.md` (Russian original), appendix A6, "Minor"

A consolidated list of minor remarks:

1. `qemu/src/lib.rs:63` — `STATE_NAMES[argmax]` without a guard, while `firmware/a` uses `.get(...).unwrap_or("?")`. Make them consistent (on NaN the `.unwrap()` at L47 would panic earlier anyway).
2. `qemu/src/windows.rs:5` — the doc says "included by the firmware (`qemu/src/main.rs`)", while the module is actually included by `lib.rs` (`pub mod windows`). A doc-sync thread.
3. `qemu/Cargo.toml:40-41` — the footprint numbers are built with the default `opt-level = 3`; for size claims it is honest to add (or at least mention in the README) the `opt-level = "z"` variant — the relative kernel comparison survives that.
4. `scripts/qemu-parity.sh` — parity coverage: 4 happy-path windows (the first row of each class), no regenerative check of `windows.rs` ↔ `model_a.val.csv` (drift on retraining). Add a test/step recomputing `gen-qemu-windows.py` into a temp dir and comparing.
5. `qemu/src/uart.rs:32` — busy-wait TX without a timeout: on real hardware a hang (QEMU's backend always drains) — already honestly documented; add a bounded loop when porting.
