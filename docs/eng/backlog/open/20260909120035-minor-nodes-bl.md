# Minor: nodes

- **Severity**: minor
- **Component**: nodes
- **Source**: code review `backlog/20260909120000-review.md` (Russian original), appendix A2, "Minor"

A consolidated list of minor remarks:

1. `a.rs:56`, `q.rs:43` — `partial_cmp(b).unwrap()` panics on NaN. Replace with `f32::total_cmp`: `max_by(|(_, a), (_, b)| a.total_cmp(b))`.
2. `sim_source.rs:94` — `record.get(2)?.to_string()` + the `last_state` swap — a String allocation **per row** (~96k per 60-second run) for a "diagnostics only" field. Remove it or stop storing it (parse only `t_ms`/`current_a`).
3. `status.rs:132` — `mem::take` leaves the Vec with capacity 0 → ~7 reallocations per window. A two-buffer pool (swap with a spare) removes hot-loop allocations; the firmware track will notice.
4. DRY between A and Q: argmax is duplicated (`a.rs:53-58` / `q.rs:40-46`), `RunSummary`+loops are similar; the three MQTT-wrapping branches in `bin/node.rs:71-175` are near copies (meta → run → end → println). Extract a shared helper.
5. `mqtt_sink.rs:149-173` — a string dispatcher with an `else` → the Q topic: a row with a typo in `node` silently goes to `q/verdict`. An explicit match on `NodeKind` or a `debug_assert!` on the else branch.
6. `status.rs:4-6` — the doc claims "follows the capture schema family (`features_cli::capture`)" but the actual schema `node,run_id,t_ms,state` ≠ `CAPTURE_HEADER = [t_ms,node,run_id,value,state,note]` (`capture.rs:10`). Soften the wording or unify the schemas.
7. `a.rs:102`, `q.rs:69`, `p.rs:122` — `while let Ok(...)` silently ends the run on `SourceError::Sensor` too (not only `Exhausted`), then publishes the regular end marker — the aggregator cannot tell a break from the end. Distinguish the branches at least by a log/counter.
8. `examples/qemu_host_ref.rs:28` — `STATE_NAMES[argmax]` without a clamp (unlike `a.rs:117`); unreachable now, but inconsistent.
9. `lib.rs:31-39` — the `skeleton_imports` test guarantees nothing beyond module compilation; remove or keep deliberately.
