# Minor: mqtt-min

- **Severity**: minor
- **Component**: mqtt-min
- **Source**: code review `backlog/20260909120000-review.md` (Russian original), appendix A4, "Minor" + test gaps

A consolidated list of minor remarks:

1. `bin/broker.rs:3` vs `:16-19` — the doc comment promises `[--port 1883]`, the code expects a bare number; `--port 1884` silently binds the default 1883. Fix the parsing or the doc.
2. Varint reader duplication: `lib.rs:330-344` and `testing.rs:257-272` — two implementations of one protocol primitive; in the lib version the `consumed` field is used by no one. Extract to one place.
3. `lib.rs:97` — CONNACK: `body.last()` without a length check (a 1-byte CONNACK is treated as a return code); require `len == 2` and check the session-present flag.
4. `lib.rs:347-350` — `write_utf8`: `s.len() as u16` silently truncates topics/client ids over 64 KB → wire frame corruption. Return a `Result` or at least `debug_assert!`.
5. `lib.rs:159-164` — `publish` does not validate the topic: wildcards in a PUBLISH topic are forbidden (§3.3.2/§4.7), so is an empty topic (§4.7.3). The broker silently fans such a packet out to subscriptions.
6. `from_utf8_lossy` (`lib.rs:290, 299`; `testing.rs:178-179`) — invalid UTF-8 silently becomes U+FFFD instead of a protocol error (§1.5.4); two distinct invalid topics can merge into one.
7. `testing.rs:165` — only the exact `0x30` is matched: a PUBLISH with DUP/QoS>0 flags from a third-party client is silently ignored (no reject).
8. `testing.rs:203-222` — invalid filters are not rejected: `"#/x"` matches like `"#"` (over-match on everything), `"a+/b"` as a literal. Validate the filter on SUBSCRIBE and answer `0x80`.
9. No `TCP_NODELAY` on either client or broker — potential 40 ms Nagle/delayed-ACK spikes on small packets.
10. `lib.rs:170-177` — `ping()` on a subscribed connection not only errors on an interleaved PUBLISH but also *loses* it; buffer it into `pending` the way `subscribe` does.
11. `mod testing` as the home of bench-broker production code — the naming is misleading (see the renaming recommendation in `20260909120045-rec-mqtt-min-bl.md`).
12. An empty SUBSCRIBE is accepted (§3.8.3 requires ≥1); the CONNECT body is not parsed at all (any `0x10` → CONNACK 0).
13. Perf (at soak scale ~23 msg/s it is noise, but the fixes are cheap): `topic_matches` allocates 2 `Vec`s per pair (`testing.rs:204-205`); `encode_publish` re-encodes the packet per subscriber (`testing.rs:185`); `write_packet` assembles a body copy (`lib.rs:187-194`).
14. The crate has no README (the `lib.rs` docs are good though).

## Test gaps

- Assembling a packet from TCP fragments (a fake broker writing byte-by-byte with pauses) — would have covered the critical desync bug.
- Malformed packets from a client to the broker (oversize varint, garbage).
- E2e on error CONNACK/SUBACK; `send_ping` on a subscribed connection.
- Stress N publishers × M subscribers; payload >127 bytes (multi-byte varint over a socket).
