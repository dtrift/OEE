# Recommendations: ml (exporter, trainer, features-cli)

- **Severity**: recommendation
- **Component**: ml
- **Source**: code review `backlog/20260909120000-review.md` (Russian original), appendix A5, "Recommendations"

1. **The parity is self-referential**: writer → interp → microflow are all in-tree; there are no numeric expectations from real TF (the TF-file smoke test checks structure only). A cheap once-and-for-all fix: a golden fixture of ~10 (input, int8-output) pairs captured once from `tf.lite.Interpreter` on `conv1d.tflite`, asserted against interp — this ties the numeric conventions to real TFLite without Python in the repro loop.
2. **A writer compat mode**: the minimal file is deliberately microflow-specific (rank-3 input without EXPAND_DIMS, rank-4 input for FC). If the file ever needs to run under a real TFLite runtime — a compat flag emitting the wrappers the TF converter emits.
3. **Path bases in tests**: `#[model(...)]` resolves from the cwd (workspace root), `FIXTURE`/CSV — from the manifest dir (`../../ml/...`). It works, but it is a known cargo trap — worth a short comment in one of the tests.
