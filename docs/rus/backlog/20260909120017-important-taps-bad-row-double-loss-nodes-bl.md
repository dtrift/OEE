# Одна битая строка taps-датасета стоит двух потерянных вердиктов

- **Серьёзность**: важно
- **Компонент**: nodes
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А2, «Важно» №4
- **Локация**: `nodes/src/sim_source.rs:215-234` + `nodes/src/q.rs:69-91`

## Суть

Строка taps-датасета = атомарное окно (1024 сэмпла), но dirty-флаг от пропущенной строки M ставится в момент выдачи **первого сэмпла строки M+1** → `push(None)` помечает грязным окно, которое заполняется сэмплами хорошей строки M+1, и оно выбрасывается.

Итог: `verdicts = truth − 2·(bad_rows)` — ложный пропуск годной детали. Рationale «poisons the surrounding window» писался для непрерывного сигнала ноды A (там корректно); для Q, где «parts are independent events», изоляция должна быть построчной.

## Предлагаемое исправление

- Дать `TapSource` понятие границы строки (например, `next_tap()` → `Option<...>` в `run_q`, dirty на уровне строки);
- либо сбрасывать dirty-флаг аккумулятора на границе окна/строки.

## Тесты

`run_q` с битой строкой в середине (сейчас есть только тест источника, и битая строка там первая).
