# Дрейф контрактов `features-cli`: «single source of truth» никем не читается

- **Серьёзность**: важно (системная, найдена 3 ревьюерами независимо)
- **Компонент**: workspace (features-cli + все потребители)
- **Источник**: ревью `backlog/20260909120000-review.md`, раздел «Системные проблемы»; А2 «Важно» №2, А5 «Важно» №4, А6 «Рекомендации»
- **Локация**: `features-cli/src/lib.rs:48-49, 66-84`; дубликаты: `nodes/src/a.rs:29` (WINDOW=128), `nodes/src/q.rs:28` (WINDOW=1024), `ml/trainer/src/lib.rs:18,22` (TIMESTEPS=128, Q_TIMESTEPS=1024), `firmware/{a,q}` (константы с комментарием-ссылкой), `nodes/src/bin/node.rs:83,154` (частоты 1600/16_000)

## Суть

Крейт `features-cli` объявлен «single source of truth for training and firmware», но значения окон и частот продублированы руками во всех потребителях. В `nodes` зависимость на `features-cli` (`nodes/Cargo.toml:14`) вообще мертва — кодом не используется, только doc-комментариями.

Сейчас значения совпадают, но смена `window_spec` не сломает компиляцию — модели молча разойдут­ся с прошивками. Ровно тот класс багов, ради которого крейт создан.

## Предлагаемое исправление

Минимально — контрактные тесты во всех потребителях:

```rust
assert_eq!(a::WINDOW, features_cli::window_spec(NodeKind::A).unwrap().samples);
```

- в `nodes` (зависимость уже есть);
- в `ml/trainer` (dev-dependency);
- в `firmware-a`/`firmware-q` (host-тесты, зависимость уже есть);
- для `qemu` можно добавить зависимость — features-cli `#![no_std]`.

Лучше — вычислять константы из `window_spec` (это `const fn`).

Заодно: либо начать использовать зависимость в `nodes`, либо убрать её — «мёртвый» path-dependency маскирует, что контракт дублирован.
