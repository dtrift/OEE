# Паника `clamp(1, 0)` в `split` при отсутствующем классе

- **Серьёзность**: критично
- **Компонент**: ml-trainer
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А5, «Критично» №1
- **Локация**: `ml/trainer/src/data.rs:100-105`

## Суть

`cut.clamp(1, idx.len())`: если у класса ноль окон, `clamp(1, 0)` паникует («min > max»). Триггер вполне реален:

- `--task q` на taps-датасете без брака (только «good») на week-4 bring-up;
- передача неполного набора CSV для A.

`load_csv` валидирует диапазон меток, но не присутствие всех классов; `split` возвращает кортеж, а не `Result` — пайплайн падает с невнятной диагностикой после успешной загрузки CSV.

## Предлагаемое исправление

- В `load_datasets` проверять `counts[c] > 0` для всех `0..num_classes` и возвращать `Err("class 'cracked' has no windows in the given datasets")`.
- В `split` — `if idx.is_empty() { continue; }` как страховка.
