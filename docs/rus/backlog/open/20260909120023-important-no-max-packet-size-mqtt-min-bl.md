# Нет лимита remaining length при аллокации

- **Серьёзность**: важно
- **Компонент**: mqtt-min
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А4, «Важно» №2
- **Локация**: `mqtt-min/src/testing.rs:132`, `lib.rs:203`, `lib.rs:228` (`vec![0u8; len]`)

## Суть

`len` с 4-байтового varint достигает 268 435 455 — один 4-байтовый заголовок даёт мгновенную аллокацию 256 МБ:

- у брокера — от битого/злонамеренного клиента;
- у клиента — от битого/злонамеренного брокера (достижимо в связке с багом `20260909120003-critical-midpacket-retry-desync-mqtt-min-bl.md`: после десинка payload-байты интерпретируются как заголовок).

Для CI-процесса loopback-тестов это OOM.

## Предлагаемое исправление

Константа `MAX_PACKET_SIZE` (например, 1 МБ — с запасом над любым payload бенча); при превышении — ошибка и закрытие соединения.

Лучше — вместе с `20260909120045-rec-mqtt-min-bl.md`: вынести framing (varint + чтение полного пакета + лимит) в один приватный модуль для клиента и брокера.
