# Пробелы в тестах детерминизма и независимости каналов

- **Серьёзность**: важно
- **Компонент**: line-simulator
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А1, «Важно» №7
- **Локация**: `line-simulator/tests/determinism.rs`, `belt.rs:179-193`

## Суть

- (a) Headline-контракт «запрос одного канала не меняет остальные» не проверен end-to-end: нет теста «`--out a --taps-dataset t`» vs «`--out b`» → `a == b`. Существующий тест `belt_stream_is_independent_of_the_tap_stream` проверяет лишь что потоки *различаются* — необходимое, но не достаточное условие независимости.
- (b) Бит-детерминизм `--dataset` / `--taps-dataset` / `--belt-events` не проверен на уровне бинарника (юнит-тесты есть, интеграционного нет).
- (c) `determinism.rs:24-25` — фиксированные имена файлов в `/tmp` без очистки: два параллельных запуска теста (два чекаута, один CI-раннер) дают коллизию и мигающий фейл.

## Предлагаемое исправление

- CLI-тест комбинированного запуска (a) — он же станет регрессионным на будущие изменения расхода RNG.
- Интеграционный тест бит-детерминизма всех режимов (b).
- `tempfile`/имя процесса для временных файлов + удаление после сравнения (c).
