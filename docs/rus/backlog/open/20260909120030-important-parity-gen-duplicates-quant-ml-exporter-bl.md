# `parity_gen` дублирует формулу квантования входа из interp

- **Серьёзность**: важно
- **Компонент**: ml-exporter
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А5, «Важно» №5
- **Локация**: `ml/exporter/src/bin/parity_gen.rs:45-48` vs `ml/exporter/src/interp.rs:102-108`; попутно `parity_gen.rs:66-68`

## Суть

Один и тот же код `(v/scale).round_ties_even() + zp … clamp` живёт в двух местах. При дрейфе (например, поменяли режим округления только в interp) фиксстуры генерируются на входе A, а ожидания интерп посчитала на входе B — parity-тест измеряет не ту пару, падая запутанно или проходя ложно.

Попутно: `io_quants(&interp)` игнорирует параметр и перечитает файл с диска.

## Предлагаемое исправление

- Выставить `pub fn quantize_input(&self, values: &[f32]) -> Vec<i8>` (или возвращать квантованный вход из `run`) и переиспользовать в `parity_gen`;
- `io_quants` сделать методом `InterpModel`.
