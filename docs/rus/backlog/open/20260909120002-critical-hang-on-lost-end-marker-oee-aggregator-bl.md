# Вечное зависание агрегатора при потере `end`-маркера

- **Серьёзность**: критично
- **Компонент**: oee-aggregator
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А3, «Критично» №1; найдено независимо тремя ревьюерами (nodes, aggregator, firmware-bridge)
- **Локация**: `oee-aggregator/src/aggregator.rs:393-452`; сопутствующие: `nodes/src/bin/node.rs:89,121,157`, `oee-aggregator/tests/experiment.rs:228-231`

## Суть

Цикл `run()` ждёт `end`-маркеры от всех ожидаемых узлов. Если хотя бы один узел:

- упал (kill -9, паника до `publish_end` — например, `partial_cmp().unwrap()` на NaN в `a.rs:56`/`q.rs:43`),
- потерял сеть,
- или единственная QoS 0 публикация маркера не дошла (`publish_end` в ноде — одна попытка, результат игнорируется),

агрегатор висит молча: `next_message` таймаутится, пингуется, ждёт бесконечно. Документация обещает «mid-run disconnects abort the run», но обрыв *узла* при живом брокере как раз не abort.

Тестовый harness зависает тоже: `experiment.rs:228-231` делает `aggregator_thread.join()` без таймаута — CI повиснет вместо фейла.

## Предлагаемое исправление

- Общий дедлайн/idle-таймаут в `Config`: «нет новых событий N секунд после того, как хотя бы один узел закончился» → `Err` с диагностикой, какие узлы не завершились.
- CLI-флаг `--max-wait-s` с разумным дефолтом.
- В тестах — обёртка с таймаутом (канал + `recv_timeout` вместо `join`).
- Со стороны нод — ретрай `publish_end` (отдельная карточка `20260909120015-important-end-marker-no-retry-nodes-bl.md`).

## Тесты

«Узел умирает без `end` → агрегатор по таймауту возвращает ошибку с именами незавершившихся узлов».
