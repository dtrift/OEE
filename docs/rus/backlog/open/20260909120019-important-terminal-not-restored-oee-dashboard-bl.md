# Терминал не восстанавливается на ошибочном выходе

- **Серьёзность**: важно
- **Компонент**: oee-dashboard
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А3, «Важно» №2
- **Локация**: `oee-dashboard/src/main.rs:72-79`

## Суть

`event::poll(TICK)?`, `event::read()?`, `terminal.draw(...)?` — любая io-ошибка выходит из `main` через `?` **мимо** `ratatui::restore()`. Паники покрыты hook-ом, ошибки — нет: пользователь получает сломанный терминал (raw mode + alternate screen), сообщение об ошибке уходит в «битый» stdout.

## Предлагаемое исправление

Вынести цикл в функцию и гарантированно вызывать `ratatui::restore()` на любом выходе (drop-guard или `match` вокруг результата цикла).
