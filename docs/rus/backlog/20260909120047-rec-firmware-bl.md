# Рекомендации: qemu + firmware

- **Серьёзность**: рекомендация
- **Компонент**: firmware
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А6, «Рекомендации»

1. **Закрепить contract-константы тестами**: `firmware-a`/`firmware-q` уже зависят от `features-cli` — host-тест `assert_eq!(WINDOW, features_cli::window_spec(NodeKind::A).unwrap().samples)` (и для Q); для `qemu` можно добавить зависимость (features-cli — `#![no_std]`). Подробнее: `20260909120007-important-features-cli-contract-drift-workspace-bl.md`.
2. **Property-style трасса после фикса P** (`resolved/20260909120005-critical-counts-levels-not-edges-firmware-p-bl.md`): прогнать `bounce/held-high/wrap` из прошивки против host `nodes::p::EdgeCounter` на одинаковых входах — это и есть заявленная «зеркальность».
3. **CI**: добавить job `qemu` и `--release` в job `firmware` — см. `20260909120031-important-qemu-not-in-ci-ci-bl.md`.
