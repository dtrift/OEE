# Потерянный publish статуса A не восстанавливается

- **Серьёзность**: важно
- **Компонент**: nodes
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А2, «Важно» №5
- **Локация**: `nodes/src/mqtt_sink.rs:80-113`

## Суть

При разрыве соединения статус теряется навсегда: следующий publish переподключится, но отправит уже *новое* изменение. Пейлоады P несут кумулятивный `count` — агрегатор восстановит пропуск; статусы A — это change-events, потерянное изменение искажает Availability до следующей смены.

## Предлагаемое исправление

Полное решение — QoS ≥ 1 / очередь на стороне `mqtt-min` (вне текущего скоупа). Дешёвый минимум здесь: один ретрай потерянного сообщения после переподключения.
