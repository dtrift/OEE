# Рекомендации: oee-aggregator + oee-dashboard

- **Серьёзность**: рекомендация
- **Компонент**: oee-aggregator
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А3, «Рекомендации»

## Тесты, которых не хватает

- Битый payload именно по wire-пути: в `aggregator_pipeline.rs` все payload ручные и валидные — corrupt-изоляция проверена только на `Aggregation`.
- Узел умирает без `end` → агрегатор по таймауту возвращает ошибку (после фикса из `20260909120002-critical-hang-on-lost-end-marker-oee-aggregator-bl.md`).
- Дубль `end`-маркера и `end` с `t_ms` меньше последнего события (код defensively обрабатывает через `final_t().max(events)`, но не запинено).
- Watermark-регрессия: источник впервые «заговорил» после чужого скачка.

## Документация

- Caveat `expect_nodes`: при `--expect a,p` вердикты Q не держат watermark — minute-окна могут закрыться до прихода поздних q-событий (финальный shift остаётся верным). Тест `watermark_ignores_unexpected_sources` фиксирует намерение, но последствие проговорить в доке `Config::expect_nodes`.
- Дедлайн из критичной карточки логично оформить CLI-флагом `--max-wait-s` с разумным дефолтом — сохранит «hang-free» семантику и для ручных прогонов.
