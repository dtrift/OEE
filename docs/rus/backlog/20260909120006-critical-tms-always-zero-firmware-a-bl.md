# Node A (прошивка): `t_ms` всегда 0 из-за целочисленного деления

- **Серьёзность**: критично
- **Компонент**: firmware-a
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А6, «Критично» №2
- **Локация**: `firmware/a/src/main.rs:83` (`const SAMPLE_US: u32 = 625` — L42)

## Суть

`t_ms = t_ms.wrapping_add(SAMPLE_US / 1000)` — `625 / 1000 == 0` в целочисленном делении, таймстампы никогда не идут. Все строки статусов выходят как `a,bench-a,0,<state>` — S3 cross-check (сверка board vs host по `t_ms`) и оконная логика агрегатора по времени ломаются молча.

## Предлагаемое исправление

Копить микросекунды (`t_us: u64`; u32 переполнится через ~71.6 мин) и делить при форматировании:

```rust
format_status(..., (t_us / 1000) as u32, ...)
```

## Тесты

Host-тест на монотонность `t_ms` в статусах.
