# Повторный SUBSCRIBE создаёт дубль подписки

- **Серьёзность**: важно
- **Компонент**: mqtt-min
- **Источник**: ревью `backlog/20260909120000-review.md`, приложение А4, «Важно» №6
- **Локация**: `mqtt-min/src/testing.rs:154-162`

## Суть

`push` без дедупа по `(conn_id, filter)`; по спеке MQTT 3.1.1 (§3.8.4) новая подписка заменяет существующую. Последствие — тихие дубли QoS-0 доставки в бенч-данные.

Вероятность низкая (текущие потребители подписываются один раз на соединение), но фикс тривиален.

## Предлагаемое исправление

`retain` + `push` (или проверка перед вставкой).
