## Что сделано (по дням декомпозиции)

- **Д0 — окружение**: крейт `mqtt-min` (см. Отступления) вместо `rumqttc`;
  проверка брокера — действие пользователя (mosquitto в песочнице нет). `nodes`
  получил CLI-бин `node` (`--kind a|q --input … --offline … [--mqtt host:port]`).
- **Д1 — узел A offline**: `nodes/src/sim_source.rs` (`SimSource` над run-CSV,
  реализация `SensorSource`), `nodes/src/status.rs` (не перекрывающиеся окна,
  анти-флап гистерезис на 2 окна, CSV-лог `node,run_id,t_ms,state`),
  `a::run_a` — полный конвейер поток → статусы с изоляцией ошибок по окнам.
- **Д2 — узел A MQTT**: `nodes/src/mqtt_sink.rs` — `oee/line1/a/status` JSON
  `{state,t_ms,run_id}` только по подтверждённым изменениям, `…/a/meta` один
  раз на старте; ленивое подключение с линейным ограниченным backoff; мёртвый
  брокер деградирует в offline-only, паник нет.
- **Д3 — канал тапов**: `line-simulator/src/taps.rs` + секция `[taps]` сценария
  (валидация, дефолты зафиксированы): синтез затухающей синусоиды на 16 кГц
  (годная 2,4 кГц/τ14 мс, треснутая 1,5 кГц/τ6 мс + грохот, seeded-блуждание
  амплитуды/частоты), тапы идут только в `Run`; выходы — обучающий датасет
  `label,state,x000..x1023` и мета `t_ms,verdict`; `scenarios/taps.toml`.
  Детерминизм: один сид → бит-в-бит те же окна.
- **Д4 — узел Q**: тренер обобщён на спецификацию задачи (`TaskSpec`, размеры
  в рантайме — `derive(Module)` у burn не несёт const generics);
  `--task q` обучает `ml/models/model_q.tflite` (11216 байт, sha256 зафиксирован
  в `model_q.metrics.txt`, confusion 121/121 + 50/50 на val);
  `nodes/src/q.rs` — `#[model]` через мост, одно окно на тап, `q::run_q` →
  `oee/line1/q/verdict`.
- **Д5 — интеграция**: оба узла в одном процессе через loopback-брокер
  (`both_nodes_one_run_with_mqtt`); argmax-паритет interp-vs-microflow на модели
  Q; смоук латентности предсказаний (100 окон A + 20 окон Q с запасом быстрее
  темпа линии, даже в debug).
- **Д6 — cut-line**: см. выше — Q остаётся.
- **Д7 — этот гейт.**

## Отступления от декомпозиции

- **В offline-песочнице нет ни `rumqttc`, ни mosquitto** (крейта нет в кеше
  реестра; бинарник брокера отсутствует): MQTT реализован как `mqtt-min` —
  минимальный набор клиента MQTT 3.1.1 (CONNECT/PUBLISH QoS 0/PINGREQ,
  std-TCP, ~230 строк), формат провода зафиксирован юнит-тестами от спеки и
  inside-процессным loopback-брокером (`mqtt_min::testing`), прогоняющим весь
  путь. Тот же клиент без изменений работает против настоящего mosquitto.
  Действия пользователя, по порядку:

  1. `mosquitto -v` (или docker-сервис), ручная проверка
     `mosquitto_pub/sub` на `oee/line1/#`;
  2. `cargo run -p nodes --bin node -- --kind a --input tmp/run_base42.csv
     --offline tmp/status_a.csv --mqtt 127.0.0.1:1883` и аналог для узла Q —
     затем `mosquitto_sub -t 'oee/line1/#' -v` покажет
     статусы/вердикты и мета-строки.
- **Тренер параметризован задачей, а не размножен**: один `ModelCnn` на
  рантайм-размерах `TaskSpec` (A 128→4, Q 1024→2) — const generics не несёт
  `derive(Module)` у burn. Путь A побитово совпадает со старым пайплайном
  (артефакты регенерируются те же).
- **«WAV-подобные буферы» — это CSV**: окна тапов живут в датасетном CSV
  (линейные float, формат тренера); бинарного WAV-контейнера нет — тренер и
  узел читают один файл.
- **Времена узла Q — из мета-CSV** (выравнивание по порядку строк): схема
  датасета (`label,state,x…`) зафиксирована тренером и не несёт колонки
  времени. Битая строка сдвигает выравнивание на один тап — приемлемо, узел
  считает отброшенные окна.
- Гистерезис — 2 окна (~160 мс) — «2–3 окна» из Д2, п. 2.

## Риски (разд. 11 плана)

- «Слишком хорошие модели» — val accuracy Q равна 1,0000 (синтетические тапы,
  seeded-блуждание параметров ±8%/±15%, грохот трещины 4× шума). Риск реален,
  но ограничен по построению: ручки дрейфа живут в сценарии, финальная
  честная проверка — таблица measured vs truth недели 5 на несмотренных сидах.
- Лаг на границах у узла A: смена статуса подтверждается через ~160–240 мс
  после истинного перехода (окно + гистерезис) — виден в offline-CSV и учтён
  в сравнении с truth (проверки только в глубине интервалов). Материал отчёта,
  не дефект.
- Новых рисков форка нет: форк на этой неделе не тронут.

## Решение по неделе 5

По плану: узел P (ИК-барьер → счёт), OEE-агрегатор (A × P × Q по MQTT),
дашборд ratatui и таблица measured vs truth (главный численный результат).
Входы готовы: раскладка топиков (`oee/line1/{a,q}/…`), loopback-брокер для
тестов, пайплайны обоих узлов. Агрегатору понадобится SUBSCRIBE в `mqtt-min`
(QoS 0) — естественная первая Д-задача недели 5.

## Ретро

- Часы: не фиксировались по сессиям (повторяющийся пробел — та же пометка, что
  в неделях 2–3). Реализация — фактически одна длинная сессия.
- Loopback-брокер сперва обслуживал соединения последовательно — узлы держат
  соединения открытыми одновременно, и узел Q голодал, пока не закончил узел A.
  Урок: брокер параллелен по определению; тестовые двойники должны копировать
  это, а не только формат пакетов.
- `derive(Module)` у burn отверг const generics — один круг редизайна
  (const-generic модель → модель на рантайм-размерах). Переделка оказалась
  дешевле борьбы с derive: заодно ушли turbofish-шумы из вызовов пайплайна.
- Синтез тапов лёг почти с первого раза: физика (частота звонка + затухание),
  выбранная по спектральной интуиции, подтвердилась — модель Q разделяет
  классы без feature engineering.
