# Сценарий записи демо (неделя 6, D6)

> Целевая длина: 2–4 минуты, один дубль + резервный. Всё ниже
> воспроизводится одной командой из чистого клона (см. «Подготовка»).
> Писать полноэкранный терминал (OBS или рекордер платформы), 1080p, тёмная
> тема.

## Подготовка (до нажатия «запись»)

```bash
# из чистого клона:
cargo build --release                        # почти все крейты
docker build -t oee-qemu qemu/               # или: apt install qemu-system-arm
cargo test --workspace --release            # опционально, зелёные тесты — 10 c б-ролла
scripts/qemu-parity.sh                      # заканчивается "PARITY OK" на экране
```

Три вкладки терминала готов заранее (один рабочий каталог):

1. `scripts/qemu-parity.sh` (бит портабельности)
2. `scripts/bench.sh scenarios/week5/normal.toml 42` (бит двойника)
3. редактор с открытым `scenarios/week5/rejects.toml` (бит изменения)

## Замечания к дублю

- Дашборд открывается ДО/ВО ВРЕМЯ проигрывания узлов — это сделано
  намеренно: стенд-брокер работает на QoS 0 без ретенций и не может
  воспроизвести прошлое для опоздавшего подписчика. Пока узлы стримят
  (несколько секунд), гейджи обновляются живьём; после end-маркеров они
  замирают на финальном окне — по этому замороженному состоянию и ведёт
  сцена 2.
- Дашборду нужен терминал ≥ 80×24; прогресс узлов пишется в
  `tmp/bench/{a,p,q}.log` (скрипт показывает хвосты после `q`).
- Не начитывать вывод сборки — монтаж от команды к результату.
- Если дубль надо ужать: в сцене 1 оставить последние 10 секунд (строка
  `PARITY OK`) — ядро демо составляют сцены 2–3.

## Резервный дубль

Только сцены 2–3 (двойник + изменение брака) плюс хвост `PARITY OK`
сцены 1. Полторы минуты.
