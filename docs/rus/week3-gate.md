## Что сделано (по дням декомпозиции)

- **Д1 — shape-folding парсер (§2.1–2.2)**: `microflow-macros/src/shape_fold.rs`. Таблица
  «тензор → виртуальная форма» проходит список операторов один раз: `EXPAND_DIMS`/`RESHAPE`
  сворачиваются в виртуальные reshape, цепочка Flatten
  `SHAPE → STRIDED_SLICE → PACK → RESHAPE` вычисляется статически (разрешение `-1`, срезы в
  семантике Python, shrink-axis), реальные операторы получают эффективные формы ранга 2/4.
  Всё, что не сворачивается, прерывает сборку с номером оператора, формами и тем, что ожидалось.
- **Д2 — операторы (§2.3–2.4) + кодеген (§4)**: `ops/conv_1d.rs` (макросы) эмитит вызов кернела
  недели 2 с конверсией bias в единицы аккумулятора и ассертами геометрии (`h == 1`, `T ≥ k`,
  совпадение длины выхода); `fully_connected` (рантайм) получил генерик `WEIGHTS_QUANTS` с
  тройкой констант на выход и синтезируемый макросом нулевой bias для отброшенного конвертером
  (F6). Смена ранга между слоями становится runtime-`reshape`. `conv1d.tflite` добавлен в
  `fork/microflow/models/` (прецедент dense_spike).
- **Д3 — реальная модель через `#[model]`**: `examples/conv1d_spike.rs` +
  `tests/conv1d_model.rs` (санити softmax, детерминизм, смоук квантованного входа). Экспансия
  читается так, как требует спека §4: на входе пользовательский `Buffer2D<f32, 128, 1>`, внутри
  `Tensor4D<i8, 1, 1, 128, 1, 1>`, фильтры per-channel (8 шкал — F5 подтверждён), свёрнутый
  Flatten как один reshape `Tensor2D<_, 1, 480, 1>`, веса FC per-channel (4 шкалы — F6
  подтверждён).
- **Д4 — фичи + датасет**: `features-cli/src/features.rs` (RMS, peak, zero-crossings, спектр
  Гёрцеля на 50/150/250 Гц — no_std, фиксированные бины); `line-simulator/src/dataset.rs`
  (CLI-режим `--dataset`: окна по 128 в однородном состоянии со stride, CSV
  `label,state,x000..x127`, гистограмма классов). Добавлен `scenarios/jam_cycle.toml` — сценарии
  недели 2 держат jam на ~1% окон, для обучения это слишком мало.
- **Д5 — скрипт обучения**: `ml/scripts/train_model_a.py` (фиксированные сиды, class weights,
  full-int8 PTQ, дамп операторов, int8 confusion matrix, экспорт val-сплита для parity).
- **Д6 — мост**: `nodes` зависит от `fork/microflow` по пути (+ `nalgebra` через продублированный
  `[patch.crates-io]`); `cargo test` зелёный в обоих workspace.
- **Д7 — этот гейт.**

## Отступления от декомпозиции

- **В песочнице реализации нет TensorFlow** (только Python 3.14 + numpy, сеть закрыта): прогон
  parity против интерпретатора (Д3.2/Д6) и запуск обучения (Д5) здесь выполнить нельзя. Обе
  стороны готовы, всё исполнимое исполнено: parity-инфраструктура валидирована self-тестом
  кругового прохода (`fixture_parser_roundtrip`, нулевой diff), скрипт обучения проверен на
  синтаксис и смоделирован с проверенного `build_conv1d_model.py`. Действия пользователя, по
  порядку:

  1. `tmp/venv312/bin/python ml/scripts/dump_parity_fixtures.py` → `cargo test -p microflow --test conv1d_parity` (закрывает пункт parity);
  2. сгенерировать датасеты: `cargo run -p line-simulator -- --scenario scenarios/<s>.toml --seed <n> --dataset tmp/ds_<s>_<n>.csv`;
  3. `tmp/venv312/bin/python ml/scripts/train_model_a.py --datasets tmp/ds_*.csv` → `ml/models/model_a.tflite` + метрики; затем переключить `nodes/src/a.rs` на неё и перегенерировать parity-фикстуры с `--model ml/models/model_a.tflite --windows-npz ml/models/model_a_val.npz`.
- **Всплыл латентный баг недели 2**: `conv_1d.rs` использовал `f32::round_ties_even()`, который в
  этой сборке тулчейна есть только в std, но не в `no_std` core (гейт недели 2 гонялся по
  закешированным артефактам сборки, поэтому там не падал). Заменено на хелпер поверх
  `libm::truncf` с идентичной семантикой — золотые фикстуры недели 2 (96 кейсов, бит-в-бит)
  по-прежнему зелёные, что закрепляет эквивалентность.
- `microflow-macros/src/ops/reshape.rs` удалён (перемещён в `tmp/trash/`): фолдинг заменяет его;
  обычные reshape ранга 2/4 теперь эмитятся тем же механизмом конверсий.
- Compile-fail тесты (Д2.4) потребовали бы dev-зависимость `trybuild` (офлайн не скачивается).
  Суть закрыта иначе: фолд возвращает `Result` с сообщениями, включающими индекс оператора
  (покрыт юнит-тестами чистых хелперов), а реально misrouted-модель была поймана в разработке
  читаемым abort-ом (случай 1×1-фильтров `person_detect`).
- Баланс датасета: честное состояние — на один сид четыре сценария дают примерно
  `[idle 1136, run 4165, jam 435, overload 336]` окон; обучение использует class weights по
  обратной частоте и печатает confusion matrix. По-настоящему сбалансированный датасет требует
  либо jam-тяжёлых сценариев, либо стратифицированной выборки окон (материал недели 4, см. Ретро).
- Конвенция путей parity-фикстур: пути `#[model]` резолвятся относительно **корня workspace** во
  время компиляции (cwd rustc), а тестовые бинарники запускаются с cwd каталога пакета —
  `nodes/src/a.rs` использует `ml/models/conv1d.tflite`, собственные тесты форка —
  `models/conv1d.tflite`. Зафиксировано в NOTES.

## Риски (разд. 11 плана)

- Риск №2 (парсер сложнее ожидаемого) — снят: реальный граф сворачивается по спеке, включая
  динамическую цепочку Flatten.
- «Слишком хорошие модели» — скрипт обучения предупреждает при val accuracy выше 99,5%, а
  сценарии несут параметры дрейфа/шума; финальный вердикт за реальным прогоном обучения.
- Сообщения `abort_call_site!` несут индекс оператора + формы + ожидание (§2.1) — проверено
  построением (conv с 1×1-фильтрами `person_detect` поначалу ошибочно ушёл в 1-D путь; ошибка
  была читаемой и привела ко второй половине дискриминатора — высоте входа).

## Решение по неделе 4

По плану: узел A end-to-end (sim → фичи → predict → MQTT) на обученной `model_a.tflite`,
узел Q (синтез звука + модель) и проверка линии среза в конце недели. Входы готовы: мост,
датасетный конвейер, скрипт обучения, parity-инструментарий.

## Ретро

- Часы: не фиксировались по сессиям (повторяющийся пробел — та же пометка, что в неделе 2).
  Реальная реализация — одна длинная сессия; оценка была ~16–19 ч.
- Ловушка закешированных артефактов (кернел недели 2 фактически не компилировался в этом
  тулчейне) стоила обходного манёвра; урок зафиксирован в NOTES: перед доверием зелёному кешу
  форсировать чистую пересборку тронутых крейтов (`touch <file> && cargo build` недостаточно,
  когда сбой старше кеша — при сомнениях `cargo clean -p <crate>`).
- Два раунда ручных ожиданий юнит-тестов были ошибочны (подсчёт окон в `dataset.rs`, семантика
  срезов Python в `strided_slice`) — обе ошибки арифметические, обе пойманы первым прогоном.
  Тот же урок, что в неделе 2: ожидаемые значения считать от первых принципов и перепроверять
  вторым методом (Python) до написания assert.
