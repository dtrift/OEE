## Д2 (вт, ~2–3 ч) — движок: как устроены `#[model]` и `predict()`

1. Прочитать структуру репо: перечень крейтов и роли каждого; список в `NOTES.md`.
2. Проследить путь модели: `.tflite` → макрос (компайл-тайм-парсинг flatbuffers) →
   сгенерированный код → `predict()`.
3. Разобрать сигнатуру `predict()`: как подать входной тензор, что возвращается.
4. Составить список поддерживаемых операторов и чего не хватает для `Conv1D`
   (3D-тензоры? `Reshape`? паддинги?).

Проверка: можете словами описать путь от файла модели до `predict()` — это половина
гейта недели.

## Д3 (ср, ~2–3 ч) — ML: тестовая модель и дамп сериализации [риск №2]

1. Собрать Keras-мини-модель по архитектуре разд. 6 плана:
   `Conv1D(8) → AvgPool → Conv1D(16) → AvgPool → FC → Softmax`, вход `(T, C)`.
2. Квантизация full-integer int8, экспорт `.tflite`.
3. Дамп операторов: список opcode'ов через `tf.lite.Interpreter` (или `flatc --json`).
4. Зафиксировать цепочку: по разд. 5 плана ожидается `Conv1D → Reshape → CONV_2D`
   над `(1, T, C)`; факт может отличаться — факт и есть результат спайка.
5. Бонус: dense-модель (`FC + Softmax`) → `.tflite` → подставить в пример форка →
   `predict()` на хосте. Так полный малый цикл «Keras → tflite → Rust» пройден сразу.

Артефакт: `spike/conv1d-serialization.md` — скрипт, фактический граф операторов,
формы тензоров, layout весов.

## Д4 (чт, ~3 ч) — движок: спека `Conv1D`

Спека — контракт для реализации недель 2–3 (правило «спека → код → тесты»). Разделы:

1. Вход из Д3: фактические op-коды, формы тензоров, layout весов и смещений.
2. Парсер: какие узлы принимать, как сворачивать `Reshape`-цепочку, атрибуты
   (stride, padding), поддержка 3D-тензоров.
3. Кернел: int8 dot-product, int32-аккумулятор, per-channel requant
   (scale/zero-point), выход.
4. Кодеген: какие структуры и буферы генерирует `#[model]` для нового случая.
5. Тесты: golden-вектора из numpy-reference; краевые случаи — `T < kernel_size`,
   `stride = 2`, `valid/same` паддинг.
6. Definition of Done недели 2 (кернел) и недели 3 (парсер + кодеген).

Проверка: «сторонний разработчик реализует по спеке без вопросов» — если нет,
дописать до этого состояния.
