3. Toy-тест уровня аккумулятора: 1 канал, k=3, T=5, stride 1, valid; значения acc

Проверка: toy-тест акк-уровня зелёный; кернел компилируется `no_std`-совместимо,
без аллокаций (по образцу `conv_2d`).

## Д2 (вт, ~2–3 ч) — движок: requant, геометрия, fused RELU

1. Requant per-channel по §3.1: `m(f) = (scale_x·scale_w[f])/scale_out`; выход =
   `clamp_i8(round_ties_even(acc·m(f)) + zp_out)`. Не «mul → round → shift»: спека
   зафиксировала f32-множитель; округление `round_ties_even` — в кернеле и reference
   одинаково.
2. Fused RELU (опции CONV_2D) — в квантованных координатах: `max(x, zp_out)`.
3. Геометрия §3.2: `T_out = floor((T−k)/stride)+1` (valid), `ceil(T/stride)` (same);
   `same`-паддинг заполняется `zp_x`, не нулём; `T < k` при valid — запрет на уровне
   кодегена (неделя 3), в кернеле — `debug_assert`; при `same` — окна добиваются `zp_x`.
4. Тесты: полный toy-тест §5.1 (zp/scale посчитаны руками — бит-в-бит); `stride = 2`,
   8 каналов, valid/same; одна строка выхода сверяется с калькулятором.

Проверка: юнит-тесты зелёные; каждый шаг requant объясняется словами.

## Д3 (ср, ~3 ч) — тесты: golden против Rust-reference [ядро гейта]

1. Reference-Conv1D в тестовой инфраструктуре форка (`fork/microflow/tests/`):
   наивная реализация строго по §3.1 — int8-вход/веса, i32-аккумулятор, requant с
   `round_ties_even`. Не float-сквозняком: пошаговая int8-семантика, иначе тест
   теряет смысл.
2. Генератор `golden-gen` (bin в форке, например `src/bin/golden-gen.rs`): кейсы §5.2 —
   T 1–64, каналы 1–8, kernel 1–7, stride 1–2, valid/same, ~100 штук, seed
   зафиксирован; фикстуры — человекочитаемые файлы в репо (например,
   `fork/microflow/tests/golden/`), перегенерация одной командой.
3. Тест кернела: читает фикстуры, сверяет выход бит-в-бит — целочисленная семантика
   детерминирована, допуск не нужен.

Проверка: все кейсы зелёные; расхождение — баг одной из сторон: разбирать по
операциям (аккумуляция → requant), а не подбором допуска.

  две частые причины.

  тесты»): спека — контракт недель 2–3.
